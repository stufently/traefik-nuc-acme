# Круг правок 1 (единственный) к вехе M7

Работа принята по существу: `renew-check` повторяет попытку ровно на известной
гонке и падает сразу на любом другом отказе, пять прогонов подряд я прогнал
руками дважды (5/5 продлений, серийники меняются, subject `C=RU`). Дефект — не в
твоём коде, а в ПРОВЕРКАХ к нему, и нашёлся он мутациями.

Спека лежит в клоне как `docs/specs/m7-round2.md`. Её надо ЗАКОММИТИТЬ вместе с
работой (`git add docs/specs/m7-round2.md`), иначе критерий чистоты дерева
недостижим.

## Где работать

Тот же клон `/home/deploy/exec-clones/traefik-stand-deflake`, та же ветка
`stand-renew-deflake`, поверх коммита `58cf6dc`. Живое дерево
`~/github/traefik-nuc-acme` не трогать, пуш из клона запрещён.

## Что проверено вживую, а что предположение

| Утверждение | Чем подтверждено |
|---|---|
| `classify_renew_log` требует три признака в одной строке через `index($0, …)` | тело функции в `scripts/stand.sh` после коммита `58cf6dc` |
| единственная отрицательная фикстура не содержит ни одного из трёх признаков | `cat docker/testdata/renew-log-other.txt` |
| подмена ЛЮБОГО из трёх условий на `1` оставляет AC-002 основной спеки зелёным | три прогона постановщика 07.09.2026, каждый с откатом файла из копии |
| пять прогонов `renew-check` подряд зелёные | два замера постановщика: 3 м 22 с и 22 с, по 5 продлений в каждом |

## Что не так

Классификатор требует три признака в ОДНОЙ строке: `unauthorized`,
`/.well-known/acme-challenge/` и `404`. Ни один из трёх не закреплён тестом:

Я по очереди заменял каждое из трёх условий в `classify_renew_log` на `1` —
то есть выбрасывал признак, — и AC-002 оставался зелёным во всех трёх случаях.
Причина простая: единственная отрицательная фикстура `renew-log-other.txt` не
содержит НИ ОДНОГО из трёх признаков, поэтому она отвергается при любой поломке
классификатора.

Чем это грозит: строка лога, где есть `unauthorized` и `404`, но речь НЕ про
`/.well-known/acme-challenge/`, будет принята за известную гонку — и
`renew-check` начнёт повторять попытки там, где обязан упасть сразу. Это ровно
та маскировка настоящей регрессии, ради запрета которой веха и делалась.

## Что сделать

1. **Три фикстуры-«почти попадания»** в `docker/testdata/`, в каждой ровно ДВА
   признака из трёх, третьего нет:
   - `renew-log-near-no-challenge.txt` — `unauthorized` + `404`, но без
     `/.well-known/acme-challenge/` (например 404 на любой другой путь);
   - `renew-log-near-no-404.txt` — `unauthorized` + `/.well-known/acme-challenge/`,
     но с другим кодом (403 или 500);
   - `renew-log-near-no-unauthorized.txt` — `/.well-known/acme-challenge/` + `404`,
     но с другой ошибкой ACME (`malformed`, `serverInternal`).
   Строки бери правдоподобные, в формате логов traefik, как в существующих
   фикстурах.
2. **Признаки в разных строках тоже не гонка.** Ещё одна фикстура
   `renew-log-near-split.txt`, где все три признака есть, но РАЗНЕСЕНЫ по трём
   строкам: классификатор обязан ответить «не гонка», потому что требование
   «в одной строке» — часть контракта.
3. **Критерий** на все четыре: каждая обязана давать РОВНО код 1.
4. **`CHANGELOG.md`** — одну строку о том, что классификатор закреплён
   фикстурами-почти-попаданиями.

## Границы

- `scripts/stand.sh` менять НЕ нужно: код правильный, дыра в фикстурах. Если
  какая-то из четырёх фикстур покажет настоящий дефект классификатора —
  остановись и доложи, не правь на ходу.
- Всё из раздела «Не трогать» основной спеки `m7-stand-renew-deflake.md`
  действует без изменений.
- Круг ОДИН. Что не влезло — в `review_backlog`.

## Критерии приёмки

- **AC-001** — почти-попадания не считаются гонкой:
  `bash -c 'for f in renew-log-near-no-challenge renew-log-near-no-404 renew-log-near-no-unauthorized renew-log-near-split; do p="docker/testdata/$f.txt"; test -f "$p" || { echo "нет фикстуры $p" >&2; exit 1; }; scripts/stand.sh classify-renew-log "$p"; rc=$?; [ "$rc" -eq 1 ] || { echo "$f: ожидался код 1, получен $rc" >&2; exit 1; }; done'`
- **AC-002** — настоящая гонка по-прежнему узнаётся:
  `bash -c 'scripts/stand.sh classify-renew-log docker/testdata/renew-log-retryable.txt'`
- **AC-003** — прежняя отрицательная фикстура не сломалась:
  `bash -c 'scripts/stand.sh classify-renew-log docker/testdata/renew-log-other.txt; rc=$?; [ "$rc" -eq 1 ] || { echo "ожидался код 1, получен $rc" >&2; exit 1; }'`
- **AC-004** — дерево чистое и `scripts/stand.sh` не изменён вехой:
  `bash -c 'test -z "$(git status --porcelain -- . ":(exclude)report.json" ":(exclude)report-blocked.md")" && test -z "$(git diff --name-only HEAD~1..HEAD -- scripts/stand.sh)"'`

⚠️ **Своя проверка ДО отчёта (в `note` к AC-001, машинным критерием не
оформляется).** По очереди замени в `classify_renew_log` каждое из трёх условий
на `1`, убедись, что при КАЖДОЙ замене AC-001 краснеет, и откати правку КОПИЕЙ
файла — `git checkout --` здесь применять нельзя. В `note` напиши, какая
фикстура упала на какой замене.

## Контракт на невыполнимое

Требование спеки противоречит коду или другому требованию — ОСТАНОВИСЬ, положи
`report-blocked.md` с воспроизведением и фактическими значениями, закоммить его
и доложи. Обходить несовместимость запрещено.

Контракт отчёта и авторевью — как в основной спеке: `report.json` с записью на
каждый критерий, `ask-codex` и `ask-agy` параллельно до отчёта, поля
`review_codex`, `review_agy`, `review_backlog`. Коммит в ветку
`stand-renew-deflake`, `git add` по именам, пуша нет.
