# traefik-nuc-acme

[English](README.md)

Traefik с **настраиваемым Subject в ACME CSR**: запрос на подпись сертификата,
который Traefik отправляет в удостоверяющий центр по протоколу ACME, может
содержать `C=RU`, название организации или любое другое поле Distinguished Name
(DN, различительного имени), которое требует УЦ.

Проект создан для [НУЦ](https://nuc-acme.voskhod.ru) (Национального
удостоверяющего центра, российского государственного ACME-УЦ под управлением
НИИ «Восход»), который, в отличие от Let's Encrypt, требует указать страну в
CSR. Сама возможность универсальна: она подходит для любого УЦ с таким же
требованием.

## Что это

**Набор патчей** для зафиксированного выпуска исходного Traefik и Dockerfile,
который собирает бинарный файл с этими патчами. Traefik распространяется по
лицензии MIT, и его уведомления сохранены; этот репозиторий содержит патч,
а не копию исходного кода Traefik.

## Чем этот проект НЕ является

- **Это не форк lego.** Патч сам формирует CSR средствами Go `crypto/x509`
  и передаёт его в штатный `lego.ObtainForCSR()`. Зависимость lego остаётся
  неизменённой.
- **Это не форк Traefik.** Исходный код оригинального проекта не включён в этот
  репозиторий. При сборке скачивается зафиксированный выпуск и применяется патч.
- **Это не плагин Traefik.** Система плагинов Yaegi в Traefik предназначена для
  промежуточных обработчиков HTTP, а не для механизма получения сертификатов
  ACME, поэтому требуется патч самого Traefik.

## Почему исходные проекты этого не поддерживают

Задача `go-acme/lego#2433` («Добавить возможность указывать Subject Distinguished
Name в сертификате») открыта с 2025-02-11. Иногда в качестве основы для этого
упоминают `go-acme/lego#2423`, но это не так: там добавили поддержку адресов
*электронной почты* в CSR, а не Subject DN.

## Настройка

```yaml
certificatesResolvers:
  nuc:
    acme:
      caServer: https://nuc-acme.voskhod.ru/acme/api/v1/directory
      keyType: RSA2048
      httpChallenge:
        entryPoint: web
      csrSubject:
        country: RU
        organization: "Example LLC"
```

Все поля `csrSubject` необязательны; если не указывать весь блок, поведение
штатного Traefik воспроизводится без изменений, с точностью до байта.

## Пресет НУЦ

`presets/nuc.yml` — статическая конфигурация Traefik для
[НУЦ](https://nuc-acme.voskhod.ru) (`https://nuc-acme.voskhod.ru/acme/api/v1/directory`).
Скопируйте её, замените значения `REPLACE-ME` (`email`, `organization`,
`locality`, путь к хранилищу) и оставьте `csrSubject.country: RU`.

**Работа с боевым НУЦ НЕ ПРОВЕРЕНА из-за отсутствия доступа.** Для выпуска
сертификатов в боевом УЦ нужна аккредитация, которой нет ни у кого из участников
проекта. Причина пробела в проверке — отсутствие доступа, а не недосмотр;
проверка отложена до получения доступа. На 2026-09-07 проверены URL каталога
ACME, цепочка TLS и отсутствие EAB. Не проверены и недоступны для проверки из
этого окружения: выпуск и продление сертификатов. Значение `keyType: RSA2048`
выбрано по общедоступной документации RSA DV; отвергает ли УЦ ключи EC,
остаётся открытым вопросом по той же причине. Используйте пресет как отправную
точку, а не как проверенную боевую конфигурацию.

Боевой НУЦ не проверен: доступа к нему нет, для выпуска нужна аккредитация.
Проверка отложена до её появления — это дыра по доступу, а не по недосмотру.

### Набор сертификатов УЦ (не включён в образ)

Сертификат `nuc-acme.voskhod.ru` подписан в цепочке Russian Trusted Root CA
(Минцифры). Этого корневого сертификата нет ни в одном стандартном хранилище
доверия, поэтому обычный `curl` завершает TLS-рукопожатие с ошибкой ещё до начала
ACME. Промежуточный УЦ, выдающий сертификаты, уже менялся (2022 → 2024).
Встроенная в образ копия незаметно устарела бы при следующей смене: рукопожатие
не проходило бы, но ничто не указывало бы на устаревший файл внутри образа.
Поэтому набор сертификатов собирается скриптом с зафиксированными хешами sha256
и монтируется извне.

```bash
scripts/nuc-ca-bundle.sh -o nuc-ca.pem
```

Параметры `--root-sha256` / `--sub-sha256` позволяют переопределить хеши после
смены сертификатов, не редактируя скрипт. При несовпадении хеша скрипт
завершается с ненулевым кодом и не создаёт и не заменяет целевой файл.

Смонтируйте пресет и набор сертификатов, затем запустите Traefik (точка входа
образа сначала проверяет `csrSubject`):

```bash
docker build -t traefik-nuc-acme:3.7.13-nuc.1 -f Dockerfile .
docker run --rm \
  -v "$PWD/presets/nuc.yml:/etc/traefik/traefik.yml:ro" \
  -v "$PWD/nuc-ca.pem:/etc/traefik/ca/nuc-ca.pem:ro" \
  -v acme-data:/data \
  -p 80:80 -p 443:443 \
  traefik-nuc-acme:3.7.13-nuc.1
```

### Ловушка: промежуточный УЦ 2022 года не является издателем

Не используйте широко тиражируемый
`https://gu-st.ru/content/lending/russian_trusted_sub_ca_pem.crt` (серийный номер
`1002`, выпущен в 2022 году). Это **не** издатель текущего конечного сертификата:
SKI того файла — `D1:E1:71:0D…`, а AKI конечного сертификата — `77:3D:D9:39…`.
Берите сертификат издателя по адресу из расширения Authority Information Access
(AIA) конечного сертификата:
`http://nuc-cdp.voskhod.ru/cdp/subca_ssl_rsa2024.crt` (это PEM, несмотря на
расширение `.crt`; не декодируйте его как DER). Рабочий набор состоит из этого
промежуточного сертификата и
`https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt`.

## Проверка перед запуском

Штатный Traefik пропускает ACME resolver, если тот не смог инициализироваться,
и продолжает работу сервера. Поэтому при некорректном `csrSubject` такой
resolver не выпускает сертификаты, а причина видна только в журналах.
Без предварительной проверки опечатка может привести к незаметному отсутствию
сертификатов.

Точка входа образа сначала запускает `/traefik validate-csr-subject "$@"`.
Эта команда использует те же экземпляры загрузчиков конфигурации, что и Traefik:
обработка устаревших настроек, файл, флаги, затем переменные окружения. Она
учитывает `--configfile` и обычные пути поиска файлов Traefik; отдельная
конфигурация не разбирается. Каждый ACME resolver проверяется по существующим
правилам `CSRSubject.Validate()`, в порядке имён. Resolver без ACME и пустые
Subject допускаются.

При ошибке команда выводит в stderr строку наподобие следующей и завершается
с кодом 1:

```text
invalid CSR subject in resolver "nuc": CSR subject country must contain exactly two ASCII letters
```

При успехе команда выводит `csrSubject OK` в stdout и завершается с кодом 0.
Только после этого точка входа заменяет себя сервером Traefik через `exec`.
Ненулевой код проверки возвращается без изменений, поэтому сервер не запускается
с некорректным Subject. Штатное поведение инициализации resolver не изменено.

Проверку можно выполнить напрямую, без запуска сервера:

```bash
docker run --rm -v "$PWD/traefik.yml:/etc/traefik/traefik.yml:ro" \
  traefik-nuc-acme:3.7.13-nuc.1 validate-csr-subject \
  --configfile=/etc/traefik/traefik.yml
```

Точка входа передаёт `healthcheck`, `version` и `validate-csr-subject` напрямую,
сохраняя поведение служебных команд. Эта защита проверяет Subject в CSR;
остальные ошибки конфигурации ACME по-прежнему обрабатываются самим Traefik.

## Состояние проекта

Веха 4: пресет НУЦ (`presets/nuc.yml`) и монтируемый извне набор сертификатов УЦ
(`scripts/nuc-ca-bundle.sh`). Выпуск сертификатов в боевом НУЦ остаётся
НЕПРОВЕРЕННЫМ, поскольку без аккредитации нет доступа к УЦ. Предыдущие вехи:
проверка Subject в CSR с запретом запуска при ошибке, образ с патчем и
интеграционный стенд с Pebble.

## Образ Docker

Тег: `traefik-nuc-acme:3.7.13-nuc.1`. Никогда не используйте просто `3.7.13`:
такой тег можно принять за официальный Traefik.

```bash
docker build -t traefik-nuc-acme:3.7.13-nuc.1 -f Dockerfile .
```

Образ собирается **без Node и без веб-панели управления**.
`api.dashboard` работать не будет. Это намеренный компромисс, позволяющий
скомпилировать бинарный файл без доступа к сети из архива выпуска и патча,
без инструментов yarn/Node при сборке.

Публикация для нескольких архитектур выполняется через `scripts/release.sh`.
По умолчанию и с `--dry-run` скрипт только выводит план; для публикации нужен
`--push`. Скрипт никогда не встраивает учётные данные реестра.

## Интеграционный стенд

Traefik с патчем и Pebble (имитация ACME-сервера Let's Encrypt). Проверка
HTTP-01 выполняется на порту 5002. Тестовый домен `stand.traefik-nuc.test` —
сетевой псевдоним сервиса Traefik в Docker. Обратный прокси nginx перед Pebble
записывает тела ACME-запросов, чтобы `csr-dump` мог вывести CSR, который
действительно отправлен в УЦ (Pebble не переносит Subject в выданный конечный
сертификат).

```bash
scripts/stand.sh up
scripts/stand.sh wait
scripts/stand.sh csr-dump | openssl req -noout -subject
scripts/stand.sh dump-cert | openssl x509 -noout -subject
scripts/stand.sh renew-check
scripts/stand.sh down
```
