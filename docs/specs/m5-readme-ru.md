# Веха M5 — README на русском

## Зачем веха

Целевой потребитель проекта — пользователи НУЦ, российского гос-ACME-CA.
Документация у проекта только английская. Русская версия здесь не «локализация
для галочки», а язык той аудитории, ради которой патч и написан.

## Где работать

Клон, ветка `m5-readme-ru`. Спека лежит в клоне как `docs/specs/m5-readme-ru.md`
и уже входит в коммит ветки — отдельно коммитить её не нужно, править и удалять
нельзя.

Веха **не трогает код**: ни патч, ни скрипты, ни пресет, ни английский README.

## Что сделать

Один файл `README.ru.md` — полный русский эквивалент `README.md`.

- Структура заголовков совпадает с английской один в один: столько же
  заголовков, в том же порядке, на том же уровне вложенности.
- **Команды, пути, URL, имена файлов и версии не переводятся.** Блоки кода
  переносятся побайтово. Переводится проза вокруг них.
- Термины: `csrSubject`, `caServer`, `entryPoint`, `keyType` и прочие имена
  опций Traefik остаются как есть, латиницей.
- Взаимные ссылки: в `README.md` — строка со ссылкой на `README.ru.md`, в
  `README.ru.md` — на `README.md`. Это ЕДИНСТВЕННОЕ разрешённое изменение
  английского файла.
- Формулировка про боевой НУЦ переносится по смыслу, а не по букве: доступа к
  УЦ нет, для выпуска нужна аккредитация, проверка отложена до её появления.
  Это дыра **по доступу**, а не по недосмотру — в русском тексте это должно
  читаться так же однозначно, как в английском.
- Запись в `CHANGELOG.md`.

## Что проверено вживую, а что предположение

Проверено мной 2026-09-07 прогоном, на это опирается спека:

- `scripts/readme_parity.py` уже лежит в репозитории и работает: при отсутствии
  `README.ru.md` все восемь проверок отказывают, а копия английского файла,
  выданная за перевод, валится на `cyrillic` (14 разделов из 15) — то есть
  критерий AC-003 обходной реализацией не берётся;
- список файлов для AC-006 выводится ИЗ английского README, а не задан
  списком: требовать в переводе то, чего нет в оригинале, было бы дефектом
  постановки (первая версия проверки этим и болела);
- `./scripts/nuc_preset_checks.sh` на текущем дереве зелёный — AC-011 опирается
  на него.

Предположений в этой вехе нет: она про текст, внешних систем не касается.

## Критерии приёмки

Коды возврата разведены: у падения по среде и по сути они разные.

- **AC-001** — файл существует и непуст:
  `bash -c 'test -s README.ru.md || { echo "нет README.ru.md" >&2; exit 3; }'`
- **AC-002** — структура заголовков совпадает с английской один в один:
  `bash -c 'python3 scripts/readme_parity.py headings'`
- **AC-003** — 🚩 перевод ДЕЙСТВИТЕЛЬНО перевод: в каждом разделе не меньше 80
  кириллических знаков. Копия английского файла этот критерий не проходит, и в
  этом его смысл — проверено зондом, копия валится на 14 разделах из 15:
  `bash -c 'python3 scripts/readme_parity.py cyrillic'`
- **AC-004** — 🚩 блоки кода перенесены побайтово, а не переведены:
  `bash -c 'python3 scripts/readme_parity.py code'`
- **AC-005** — набор ссылок совпадает в обе стороны:
  `bash -c 'python3 scripts/readme_parity.py urls'`
- **AC-006** — каждый файл, названный в оригинале, назван и в переводе:
  `bash -c 'python3 scripts/readme_parity.py paths'`
- **AC-007** — версии из `upstream.lock` присутствуют в переводе:
  `bash -c 'python3 scripts/readme_parity.py pins'`
- **AC-008** — 🚩 про боевой НУЦ сказано, что дело в ДОСТУПЕ и аккредитации:
  `bash -c 'python3 scripts/readme_parity.py access'`
- **AC-009** — взаимные ссылки на месте:
  `bash -c 'python3 scripts/readme_parity.py links'`
- **AC-010** — 🚩 английский README не переписан: относительно базы ветки
  (`m5-base`) в нём изменено не больше двух строк — ссылка на русскую версию.
  Считается от базы, а не от `HEAD~1`: числа коммитов в ветке не знает никто:
  `bash -c 'n=$(git diff "$(git merge-base HEAD m5-base)" --numstat -- README.md | awk "{s+=\$1+\$2} END {print s+0}"); [ "$n" -le 2 ] || { echo "в README.md изменено строк: $n" >&2; exit 3; }'`
- **AC-011** — продукт прошлых вех не тронут:
  `bash -c 'git diff --quiet HEAD -- patches/ scripts/ presets/ || { echo "тронут код" >&2; exit 3; }; ./scripts/nuc_preset_checks.sh >/dev/null || { echo "проверки пресета красные" >&2; exit 4; }'`
- **AC-012** — дерево чистое и никаких GitHub Actions:
  `bash -c 'test -z "$(git status --porcelain -- . ":(exclude)report.json" ":(exclude)report-blocked.md")" || { echo "дерево грязное" >&2; exit 3; }; test -z "$(git ls-files -- ".github")" && test ! -d .github || { echo "появился .github" >&2; exit 4; }'`

## Контракт отчёта

`report.json` в корне клона, по критерию на каждый AC:

```json
{"criteria": [{"id": "AC-001", "status": "pass|fail|blocked",
  "command": "<команда-доказательство>", "rc": 0, "note": "…"}]}
```

`command` обязана быть перезапускаемой — её перезапустит приёмка. Не дописывай
в хвост `printf`/`echo`: хвост съедает код возврата. Всё для глаз — в `note`.

## Не трогать

- `patches/`, `.upstream/`, `scripts/`, `presets/`, `Dockerfile`,
  `docker/` — веха только про текст.
- `README.md` — кроме одной строки со ссылкой на русскую версию.
- `docs/specs/` — постановка не правится.
- `.github/` — в этом репозитории не должно быть GitHub Actions ВООБЩЕ.

## Контракт на невыполнимое

Требование невыполнимо или противоречиво — **остановись и доложи** в
`report-blocked.md`: что требовалось, чем проверял, почему не выходит.
Подгонять текст под критерий вместо перевода запрещено: критерий AC-003 стоит
именно для того, чтобы копия английского файла не прошла за перевод.
